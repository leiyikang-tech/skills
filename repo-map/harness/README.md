# repo-map harness

The deterministic execution layer behind **Operation 1 (`/init-deep`)** of the
**repo-map** skill. It makes the AGENTS.md knowledge-base generation autonomous
and quality-gated with pure scripts:

- `refresh_state.py` — durable run state (init / gate / resume / status / finish).
- `gates.py` — five deterministic quality gates (no LLM judgment in pass/fail).

Both are Python 3 stdlib-only. No dependencies.

> Scope note: G1–G5 gate **Op1 (init-deep, the hierarchical AGENTS.md base)**,
> because they check file-system facts (analyzable / stack / docs produced /
> structure / builds). Op2 (profile) and Op3 (comparative research) judge
> *semantic* truth, so their pass/fail gates live in the playbooks as content
> gates (`references/op2-profile.md`, `references/op3-research.md`) — not here.

## Layout

```
harness/
  refresh_state.py   state backbone (run.json owner)
  gates.py           G1–G5 deterministic gates
  run.json           active run state (created by `init`, re-generated by install)
  README.md          this file
```

## Quick start

```bash
H={{REPO_MAP_HOME}}/harness

# 1. start a fresh run against a repo
python3 $H/refresh_state.py init --repo /path/to/repo [--out <run-dir>]

# 2. after DISCOVERY: gate it, persist only on PASS
python3 $H/gates.py g1 --repo /path/to/repo
python3 $H/refresh_state.py gate g1 --out <run-dir> --result PASS

# 3. as each phase completes, gate + persist (g2…g5)
python3 $H/gates.py g2 --repo /path/to/repo --stack node
python3 $H/refresh_state.py gate g2 --out <run-dir> --result PASS

# 4. crash mid-run? resume at the failed gate (use the same --out as init)
python3 $H/refresh_state.py resume --out <run-dir>
```

> `--out <run-dir>` is **optional and must be consistent across a given run**.
> Each state command (init/gate/resume/status/finish) accepts it; the default is
> the harness dir itself (single running repo). Pass `--out /some/dir` to hold a
> run.json for a second repo without clobbering the first.

## Gate exit codes

`gates.py <g1|g2|g3|g4|g5> --repo <path>` returns:

| code | meaning | orchestrator does |
|------|---------|-------------------|
| 0 | PASS | persist via `refresh_state.py gate <g> --result PASS`; advance |
| 1 | FAIL | `gate <g> --result FAIL --note "<why>"`; rework |
| 2 | BLOCKED | 3 attempts exhausted → escalate to oracle → ABORT |
| 3 | SKIP (G5) | `gate g5 --result PASS --note "<reason for skip>"`; acceptable only recorded |

## Gate semantics (gates.py)

| gate | checks | PASS if |
|------|--------|---------|
| g1 | entrypoints / manifests / ≥10 source files | repo is analyzable |
| g2 | stack via manifest OR dominant-language census | stack is known |
| g3 | root KB >1KB + every `--dirs` doc non-empty | docs were produced |
| g4 | ≥1 doc, no zero bytes, no >200KB, internal `](file)` links resolve | docs are sound |
| g5 | per-stack build/lint/test under `bash -o pipefail` | build/tests clean |

`--out` defaults to repo (docs written in place). `--dirs` = comma-separated
absolute subdir paths scored for per-directory docs.

## State file shape (run.json)

```json
{
  "repo": "/abs/path",
  "phase": "scoring",
  "gates": {
    "g1": {"result": "PASS", "attempts": 0, "note": ""},
    "g2": {"result": "FAIL", "attempts": 1, "note": "inconclusive"}
  },
  "artifacts": {"dirs": [], "root_kb": "", "stack": ""},
  "summary": ""
}
```

Guarantees:
- A gate only advances when it PASSes (`refresh_state.py gate`).
- Attempt counters are monotonic — a later PASS never resets a remembered FAIL,
  so a crash-resume sees the true attempt history.
- `finish --summary` marks the run complete; nothing past G5 re-opens it.

## Abort protocol

On BLOCKED (3 attempts) or an interrupted run:
1. Escalate to a consultation agent (oracle) once for a fresh approach.
2. If still blocked or the run is abandoned: write `harness/ABORTED.md` with,
   for each gate, its final result + attempt count + note. Stop there —
   a visible partial failure, never a silent hang.

## Re-runnability

Re-running `init` refuses to overwrite an existing `run.json`. To re-run from
scratch against the same repo, delete `run.json` (or pass `--out <fresh-dir>`
to init a second run in its own dir). Both scripts are idempotent at the gate
level: re-running `gates.py gX` recomputes and can be persisted again.
